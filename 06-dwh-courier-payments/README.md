# DWH для выплат курьерам

Многослойное хранилище данных для расчёта выплат курьерам сервиса доставки. Проект реализует полный цикл: от загрузки сырых данных из API курьерской службы до витрины с готовыми суммами к выплате.

## 🎯 Задача

Рассчитать суммы выплат каждому курьеру за предыдущий месяц с учётом:

- количества и суммы заказов;
- среднего рейтинга курьера;
- процента выплаты, зависящего от рейтинга (5% / 7% / 8% / 10%, но не менее фиксированной суммы за заказ);
- чаевых;
- комиссии платформы (25% от суммы заказов);
- комиссии за обработку платежа (5% от чаевых).

Отчёт строится по **дате заказа**, а не доставки — это важно для ночных заказов на стыке месяцев.

## 🏗️ Архитектура
API курьерской службы ──► STG ──► DDS ──► CDM
│ │ │
│ │ └── cdm.dm_courier_ledger (витрина)
│ └── «снежинка»: измерения + факты
└── сырые JSON

**Слои:**

- **STG** — сырые JSON из API (с пагинацией через `sort_field`, `sort_direction`, `limit`, `offset`).
- **DDS** — нормализованная модель «снежинка»: измерения (курьеры, рестораны, даты) и факты (доставки).
- **CDM** — витрина `cdm.dm_courier_ledger` с готовыми суммами выплат.

## 📊 Витрина `cdm.dm_courier_ledger`

| Поле | Описание |
|------|----------|
| `id` | идентификатор записи |
| `courier_id` | ID курьера |
| `courier_name` | ФИО курьера |
| `settlement_year` | год отчёта |
| `settlement_month` | месяц отчёта (1–12) |
| `orders_count` | количество заказов за месяц |
| `orders_total_sum` | общая стоимость заказов |
| `rate_avg` | средний рейтинг курьера |
| `order_processing_fee` | комиссия платформы (25%) |
| `courier_order_sum` | сумма к выплате за заказы (по рейтингу) |
| `courier_tips_sum` | сумма чаевых |
| `courier_reward_sum` | итоговая сумма к выплате |

## 🧮 Логика расчёта выплат

Процент выплаты курьеру зависит от среднего рейтинга `r`:

| Условие | Процент | Минимум за заказ |
|---------|---------|------------------|
| `r < 4` | 5% | 100 ₽ |
| `4 ≤ r < 4.5` | 7% | 150 ₽ |
| `4.5 ≤ r < 4.9` | 8% | 175 ₽ |
| `r ≥ 4.9` | 10% | 200 ₽ |

Итоговая выплата: `courier_order_sum + courier_tips_sum × 0.95`.

## 🔐 Переменные окружения

Перед запуском задайте переменные окружения (или настройте Connections в Airflow):

| Переменная | Назначение |
|------------|------------|
| `API_BASE_URL` | базовый URL API курьерской службы |
| `API_KEY` | ключ доступа к API |
| `API_NICKNAME` | ваш никнейм для API |
| `API_COHORT` | номер когорты |
| `API_LIMIT` | количество записей на страницу (по умолчанию 50) |
| `POSTGRES_CONN_ID` | ID подключения к PostgreSQL в Airflow |

📌 Особенности реализации
Пагинация API — корректная сортировка исключает пропуски при выгрузке больших объёмов.

Учёт даты заказа — ночные заказы, доставленные на следующий день, относятся к дате заказа.

Идемпотентность — повторный запуск DAG за тот же период не создаёт дублей.

Модель «снежинка» — нормализация измерений снижает дублирование данных.
